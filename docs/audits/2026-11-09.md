# 近期代码审计（v0.7.0）

审计基线为 `b6f8399`（v0.6.9），重点检查 v0.6.1–v0.6.9 的改动，并追溯相关 AgentCore 安装、配置和代理代码。覆盖权限迁移、聊天权限确认、SSE 恢复、会话管理、配置编辑、页面模板及发布流程。

本次确认并修复 4 项问题：

| 优先级 | 问题与触发条件 | 修复 |
| --- | --- | --- |
| P1 | 聊天默认权限从 `tools.approval_mode` 读取，但 AgentCore 实际使用 `permission.mode`。没有会话覆盖的历史会话可能把服务的 `yolo` 等模式显示为 `build`，发送时也不触发高权限确认。 | 改为读取实际配置字段；保留 API 响应字段以兼容前端；加入冲突字段测试，确保旧字段不会覆盖真实权限。 |
| P1 | 会话详情读取失败，或继承的服务权限尚未读到时，仍可发送消息。此时无法判断是否需要高权限确认。 | 权限未知时禁用输入和发送，并在提交处理器中再次阻止请求；显式使用 `build` 的新会话仍可使用。 |
| P1 | AgentCore 更新失败仅恢复二进制，不恢复 systemd unit。迁移到 root 的服务文件可能残留，使旧版本随后以新权限启动；原有自启和停用状态也可能改变。 | 将二进制、unit 和服务状态作为一次事务处理。unit 原子替换；失败时停止新服务，恢复文件和原状态；回滚不完整时不上线旧服务，并报告失败。 |
| P2 | 保存配置后重启失败时，忽略配置恢复及旧服务恢复的错误，始终声称“配置已回滚”。 | 检查并分别报告配置回滚失败和服务恢复失败；配置未恢复成功时不再重启。 |

权限字段以 [AgentCore 官方示例配置](https://github.com/kinmeic/AgentCoreGo/blob/main/agent-core.yaml) 为依据。既有 root 运行策略继续保留；该服务依旧只应执行可信任务。

验证包括：

- 原问题复现：真实 `permission.mode` 的 Go 测试，以及权限详情缺失的浏览器逻辑测试，在修复前失败、修复后通过。
- 安装故障注入：首次安装及升级在 daemon-reload、enable、restart 阶段失败；检查二进制、unit 内容和权限、自启和运行状态的恢复，及回滚自身失败的处理。
- 配置故障注入：验证正常回滚、回滚写入失败、旧服务恢复失败时的磁盘状态和错误信息。
- `go test ./...`、`go test -race ./...`、`go vet ./...`。
- `node --test internal/web/testdata/*.test.cjs`（102 项）。
- Linux amd64、arm64 交叉编译。
- `govulncheck` 在本机及 Linux amd64 目标上均未发现可达或已导入包的已知漏洞。

依赖扫描另有模块级告警 [GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932)，涉及 `golang.org/x/crypto/openpgp`。本项目不导入该包，扫描未发现调用路径；当前依赖 v0.58.0 仍是查询时的最新稳定标签，因此本次保留稳定依赖，不为未使用的包切换到伪版本。

验证边界：本地为 macOS，systemd 失败场景由故障注入验证，未对真实生产服务器执行安装、权限迁移或故障演练。此报告是限定范围的代码审计，不代表代码不存在其他缺陷。
